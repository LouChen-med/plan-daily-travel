# 高铁、飞机、酒店和市内接驳查询

## 选择可用工具
使用当前端实际提供的搜索、浏览器、地图或旅行服务连接器。先搜索定位官方页面，打开核对；网页需要交互时使用已授权浏览器。没有可用工具或登录受限时，交付明确待核实的方案，并请用户提供具体日期的查询截图。遇验证码、登录或支付停在该步骤，让用户完成；不索取密码，不无限重试。

这些链接是查询入口，不是已接入的API。Skill不要求安装依赖或注册开发者账户。若用户明确要求API自动化，再核对服务权限、接口文档、密钥和成本，另行实施。

## 默认网站与查询顺序

| 内容 | 首查网站 | 补充与核对 |
|---|---|---|
| 高铁/火车 | [12306](https://www.12306.cn/index/) | [携程火车票](https://trains.ctrip.com/TrainBooking/)；移动入口[携程火车票手机版](https://m.ctrip.com/html5/trains/)；铁路规则以12306核对 |
| 飞机 | [携程机票](https://flights.ctrip.com/online/channel/domestic) | [去哪儿](https://www.qunar.com/)进入“机票”作同条件比较；实际承运航司官网核对时刻、机场、行李与截止规则 |
| 酒店 | [去哪儿](https://www.qunar.com/)进入“酒店” | [携程酒店](https://hotels.ctrip.com/)补充比较；候选酒店官网核对地址、入住及晚到要求 |
| 市内接驳 | [高德地图](https://www.amap.com/) | 地铁、机场、车站官网核对运营时间和进出站要求 |

用户指定网站时优先使用指定网站。逐站实际查询并记录结果，不要求为了凑齐平台重复查询；主站不可读或关键字段缺失时再用补充站。平台报价只代表该平台对应房型/席别/舱位和条件，不混用会员价、早餐、税费与退改规则。最终提供具体结果页链接，不仅提供首页。

入口于2026-10-02重新核对：12306、携程机票和携程酒店页面可读取；去哪儿首页存在，但普通网页读取未返回查询表单，酒店子域重定向至首页，机票子域读取超时，故采用首页导航入口，不宣称已验证其实时查询功能。高德首页可读取。入口可访问不代表已经取得指定日期库存；需要交互时用当前可用浏览器或请求用户提供页面。

## 高铁
优先入口：[中国铁路12306](https://www.12306.cn/index/)，补充入口为[携程火车票](https://trains.ctrip.com/TrainBooking/)或[移动版](https://m.ctrip.com/html5/trains/)。上述携程专用入口于2026-10-02可读取，但未因此证明目标日库存。默认先查直达车次与对应日期余票。
1. 确认年份、乘车日期和具体车站；城市名称不能代替发站/到站。查询直达，再看有必要的接续方案。
2. 记录车次、发站、到站、出发/到达日期与时间、席别、对应票价、页面显示的余票状态、查询时间、链接。
3. 只有当日、对应日期和席别的实时查询页面支持时，才写“有票”。未开售、无票、候补、字段未读取分开报告；时刻表能证明班次时刻，不能证明余票。
4. 合并去车站、进站安检/候车、列车、出站及目的地接驳。停止检票与换乘要求按实际车站或运营方资料核对，不自行固定为通用数值。

### 高铁实际执行与失败切换
1. 使用完整日期和具体车站；“上海”不能静默替换为上海虹桥，“济南”不能替换为济南西。城市级搜索可以发现候选，但每班必须回填实际发到站及接驳。站名或站码用可核实来源，不猜测。
2. 在12306实际查询该日期/车站；普通网页只返回表单时，用当前可用浏览器填写并提交，再检查结果页的查询条件。页面日期不同、仅有首页推荐价、或历史列车详情时，只保留待核实候选。
3. 12306无法取得结果而携程可用时，切换携程同日期、同站查询；记录携程页面显示的席别、价格及库存，注明“携程显示，12306未独立核实”。“抢票”“候补”“预约”不等于有票；能购票的总体标志不证明指定席别有票。
4. 如果已提供并实际审查了查询脚本/API，才使用该能力。检查脚本文件真实存在、依赖已具备、响应属于票务数据；HTTP200的HTML错误页、空正文、验证码页均为失败，UTF-8 BOM可正常解码但不能把HTML解析成票务JSON。只有成功响应且结构符合当前接口约定，才把空列表解释为无结果；接口变更或解析失败不等于无票。不照抄缺失脚本的运行命令，也不凭说明中“官方API无需密钥”认定可用。
5. 同一来源明确失败后停止机械重试；浏览器连接失败时，不靠改URL参数或重复静态抓取证明库存。换可用入口，或请用户提供目标日期查询截图，继续核算已知条件。保留车次时刻、目标日期开行、席别库存、价格四个独立核验状态。

## 飞机
先在[携程机票](https://flights.ctrip.com/online/channel/domestic)输入出发城市、到达城市、完整日期和乘客人数，优先直飞；需要比较或补齐字段时查[去哪儿](https://www.qunar.com/)机票频道，再查实际承运航空公司官网。例如：[东方航空](https://www.ceair.com/)，[东航航班动态](https://us.ceair.com/zh/flight-result.html)。不限于此航空公司，按实际航线查询。
1. 按完整日期、出发/到达机场查询，区分同城机场与航站楼。
2. 记录航班号、实际承运方、机场/航站楼、起降日期时间、舱位/票价条件、含税价格、行李与退改规则、查询时间和来源。未读取某字段就标待核实。
3. 航班动态用于查看计划/实际状态，不等同于可购买航班或余座。代码共享不重复算作不同可行方案。
4. 核对运营方值机/登机截止时间；门到门耗时包括机场接驳、安检/候机、飞行、取行李及落地接驳。只有实时页面支持时报告具体延误，不用历史准点率保证当天准点。

### 机票实际执行与失败切换
1. 在携程搜索表单中明确单程/往返、完整去返日期和人数，提交后核对每程实际机场。城市级“上海”搜索可能同时包含虹桥与浦东，须分开计算接驳，不只比较飞行时间。优先直飞，转机需核算完整衔接。
2. 普通网页只有导航、空表单或历史航班时刻时，用可用浏览器取得对应日期结果；主站受限且去哪儿可用时，在去哪儿机票频道执行相同条件查询。保存实际结果页链接与查询时刻，不自行拼接未验证的日期参数并宣称筛选生效。
3. 比较同日期、同航班/实际承运方、同舱位和相同行李/退改条件的含税总价；记录报价所属平台及供应商。代码共享按实际承运班次合并，不当作多班可替代航班。页面“低价日历”“起价”或历史价格不能作为本次可购报价。
4. 找到候选后查实际承运航司官网的目标日期订票结果，或明确区分其季节计划表、航班动态与订票页面。季节计划/历史动态可以补充时刻候选，不能证明目标日开行或有余座。航司截止规则需要对应机场/航班；未取得规则时只标规划预留，不写成已核实截止时间。
5. 平台、航司同条件结果冲突时，说明具体差异及其对到达时间的影响，继续核对较新的目标日结果；未解决前不挑更早到达或更便宜的值凑方案。依次切换可用入口后仍缺关键字段时，请用户补目标日期页面，交付待核实候选，不宣称完成实时查询。

## 酒店
先在[去哪儿](https://www.qunar.com/)酒店频道输入目的地/会场地标、入住/退房日期、人数与房间数，筛选会场附近且满足预算的酒店；需要比较或主站无法取得结果时查[携程酒店](https://hotels.ctrip.com/)。确定候选后在该酒店官网核对地址、晚到与早餐等信息。不要默认某一连锁品牌，也不要把平台无法读取写成酒店无房。
1. 同时填写入住日、退房日、人数及房间数；午夜抵达确认属于哪一入住夜和是否可晚到。
2. 记录酒店全名、地址、次日会场通勤、可选房型、含税总价、早餐、取消条件与截止时间、入住时间、查询来源。会员价或优惠价注明资格。
3. 区分“存在这家酒店”与“指定日期的指定房型可订”。地图或搜索结果不能证明房态；未读取日期对应的预订结果就不保证有房。
4. 给出最多3个符合预算和通勤的候选，说明推荐依据，不自动订房。

## 市内路线
用实际可用地图核对完整起终点、预计出发时刻、驾车/公共交通/步行方式。记录门到门区间、步行和换乘、末班时间、来源与查询时间。即时拥堵不是未来出行时段的保证；只得到当前估算时，应明确这一限制。

## 查询失败或来源冲突
保留失败字段，不用猜测值填空。同条件来源冲突时优先运营方及时间更近的实际查询结果，并呈现影响可行性的差异。达到验证码、登录、权限或持续无结果这一障碍后，停止该来源的自动尝试，换可用来源或请用户提供截图。

发生行程冲突，或固定活动/班次衔接扣除全部耗时与缓冲后的剩余余量少于20分钟时，按SKILL.md的提问流程询问是否更改行程。查询受限但尚不能判定冲突或紧迫时，提问补齐页面或条件，不先要求用户改变日程。实际访问与实时结果必须在每次任务中重新验证。
